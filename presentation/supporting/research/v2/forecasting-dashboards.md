# Sales forecasting and dashboards in Salesforce, Dynamics 365 and HubSpot (research for issue #62)

Researched 2026-10-10. Sources are first-party vendor docs: Salesforce Help PDF and Trailhead, Microsoft Learn, and the HubSpot Knowledge Base. Each claim links to the page it came from. Where a doc didn't say something and the point comes from general product knowledge instead, it's marked *(unverified)*.

## Answer

- **All three use a category-based forecast.** Each open deal carries a **forecast category** (Pipeline / Best Case / Commit / Closed, plus Omitted or Not forecasted). The forecast grid adds up amounts per category for each person and rolls them up the manager hierarchy. Salesforce and Dynamics 365 derive the category from the stage by default, and the rep can override it. HubSpot maps deal stages to categories too.
- **The weighted forecast (amount × probability) is secondary.** HubSpot is the only one that makes it a first-class view: "Weighted amount" is the default forecast deal amount. In Salesforce and D365 the forecast grid is category-based, and probability-weighted revenue lives in reports and charts.
- **Quotas are a separate, small table: one amount per user per period (month or quarter).** Salesforce enters them in a Setup grid or by API, D365 by uploading an Excel template or calling the API, and HubSpot as "Forecastable revenue" goals. None of them derives a manager's quota from the reps' quotas automatically.
- **Manager roll-up comes from the user→manager hierarchy.** Adjustments are an *overlay* that leaves the deals unchanged. A manager can adjust a direct report's number, and Salesforce and D365 also let reps adjust their own. Each adjustment keeps a note and history. HubSpot uses **forecast submissions** instead: the rep or manager submits a number per period.
- **History is only needed for trend and "what changed" views.** The live forecast grid works from current opportunity data in all three. Microsoft **deprecated forecast snapshots on 2024-06-30** and points customers to the Forecast API for their own daily sync. Salesforce needs Historical Trending for Pipeline Inspection. HubSpot's waterfall, push-rate and historical-snapshot reports depend on property history.
- **Smallest credible set for one team:** a forecast-category field (defaulted from stage, overridable), a quota table (user × month), a by-close-month grid with Closed won / Commit / Best case / Pipeline / Weighted / Quota / Gap, and a roll-up to the manager. **Stage history and snapshots aren't needed for v2.** Add one later for the "forecast vs. last week" or "pipeline movement" views. Recommendation at the end.

**KPIs all three show:** Closed won vs. quota (attainment %), gap to quota, open pipeline by stage (funnel), Commit / Best case per period, weighted pipeline, and won vs. lost by owner. Beyond that each one shows some of: win rate, average deal size, sales cycle length, and pipeline coverage (pipeline ÷ gap). All of these come from current data. Push rate, waterfall and time in stage are the KPIs that need history.

## 3. Recommendation: the smallest credible forecast for one team

What we already have: stages with default probability (overridable), amount in EUR, close date, owner, and a single manager per user.

1. **Forecast category on Opportunity.** Choice values: Pipeline, Best case, Commit, Omitted. Closed won and Closed lost come from the closed status. Default the category from the stage (Qualification and Needs Analysis → Pipeline, Proposal → Best case, Negotiation → Commit), let the owner override it, and set it automatically on close (the D365 rule). This takes care of "best case" honestly, without guessing from probability alone.
2. **Forecast by close month,** for the current month plus the next 2 to 5, roughly the vendor defaults. Columns: **Closed won**, **Commit** (cumulative: Commit + Won), **Best case** (cumulative: Best case + Commit + Won), **Pipeline** (all open), **Weighted** (Σ amount × probability, open only, or open + won), **Quota**, **Gap** (Quota − Won), **Coverage** (open ÷ gap). This follows Salesforce's cumulative columns and HubSpot's gap and coverage. Weighted stays because v1 already shows it and HubSpot treats it as a primary view.
3. **Quota table:** user × month × amount in EUR, entered by the manager in an editable grid (Salesforce style). There's no need for Excel. The manager's own quota is a separate row, not automatic, as in all three vendors. The UI can show "sum of reports" next to it.
4. **Roll-up:** the manager view sums self + direct reports per column, plus an "expand" per rep. One level is enough for one team.
5. **Leave adjustments and submissions out of v2.** Add them later as an overlay table (user, period, amount, note, created by/on), which gives the audit trail D365 has.
6. **Dashboards:**
   - Rep "my numbers": won vs. quota (month and quarter), gap, my commit and best case, weighted pipeline, open deals closing this month, overdue close dates.
   - Manager: the same per rep in a table, a funnel by stage, won vs. lost by owner, and win rate and average deal size over the last 90 days.

**Does it need stage history or snapshots?** **No, not for a credible v2 forecast.** All three vendors compute the live forecast grid from current opportunity fields, and Microsoft removed snapshots from D365 forecasting in 2024. History only becomes necessary for:
- trend views ("commit this week vs. last week", forecast accuracy): add a **weekly snapshot table** (period, user, category totals, weighted, quota), written by a scheduled Power Automate flow. This is what Microsoft recommends instead of snapshots, using its Forecast API.
- movement views (push rate, waterfall, time in stage): add an **opportunity change log** (stage, amount, close date, category; old → new, timestamp), or turn on Dataverse auditing on those columns.

If we want trends soon after v2, add the snapshot flow early: history can't be backfilled later.
