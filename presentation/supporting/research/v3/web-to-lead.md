# Where a web-to-lead form can live for free and how it writes Leads into Dataverse (research for issue #136)

Researched 2026-10-13. Sources are Microsoft Learn, Microsoft pricing pages, Cloudflare's developer docs, HubSpot's developer docs and a Salesforce practitioner guide, all cited inline. Earlier notes in this folder are reused where they already settled a fact (`research/v3/outlook-teams.md` for what the developer tenant includes, `research/v3/jev-decision-model.md` for plug-in secrets). Context: the code app on the plain Dataverse environment `dev-salesapp`, a Microsoft 365 developer tenant with **no Azure subscription and no credit card**, and Power Apps Premium for users. The tenant has no Azure credits, so credits don't open up any option rejected below.

## Answer

- **No Microsoft route is both free and public.** Dataverse never accepts an anonymous call: every Web API request needs an OAuth token ([authenticate with OAuth](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/authenticate-oauth)). So something with a secret must stand between the public form and Dataverse. The Microsoft products that can play that part either cost money (Power Pages), are not public (Power Pages developer sites), or have unclear licensing (a Power Automate HTTP trigger).
- **Recommendation: a plain HTML form on the website, protected by Cloudflare Turnstile, posting to a small Cloudflare Worker that creates the Lead through the Dataverse Web API as an application user.**
  - **Cost: €0.** Workers Free gives 100,000 requests a day ([Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)). Turnstile Free gives unlimited challenges and is meant for "most production applications" ([Turnstile plans](https://developers.cloudflare.com/turnstile/plans/)). The Cloudflare account sits outside the tenant, so the tenant stays card-free.
  - **Auth:** an Entra app registration with a client secret, bound to an **application user** in `dev-salesapp`. Microsoft: this "doesn't consume a paid license" ([authenticate with OAuth](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/authenticate-oauth)). Give it a custom security role that can only create Leads. The secret lives in the Worker's secrets, never in the browser.
  - **The Lead arrives like any other**: Lead source = Website, Lead status = Not Contacted, a configured default Owner. The process engine plug-in (ADR 0001) runs on create, so Entry criteria and Business rules apply to web Leads too.
- **Fallback with no third-party account: Microsoft Forms plus an automated cloud flow** that creates the Lead. The Forms connector is Standard ([Forms connector](https://learn.microsoft.com/en-us/connectors/microsoftforms/)). The Dataverse step is premium, which Power Apps Premium covers only when the flow is **associated with the code app** and its owner has Premium ([Power Automate licensing FAQ](https://learn.microsoft.com/en-us/power-platform/admin/power-automate-licensing/faqs)). Free and no secrets, but no CAPTCHA, Microsoft's look and an iframe embed.
- **Not recommended:** Power Pages (¤75 per site per month for 500 anonymous users, billed yearly, so roughly €900 a year; developer sites "can't be made public"), and the Power Automate HTTP trigger (premium, anonymous access is a "legacy setting", and whether Power Apps Premium covers a flow that a stranger triggers isn't documented).
- **One licensing caution for production.** Microsoft's multiplexing guidance says "Indirectly Creating, Updating or Deleting data requires the application license" and has no clear rule for anonymous web visitors ([multiplexing guidance](https://www.microsoft.com/licensing/guidance/Multiplexing)). Power Pages is the route Microsoft licenses for external users. Building and testing on the developer tenant is fine. Before real customers use the form, confirm with Microsoft licensing whether a Worker writing Leads as an application user is allowed (see Open points). The same question applies to the Forms and HTTP-trigger routes.

## 2. How the recommended route works

1. **The form** is plain HTML on the company website (any host, including a free static host). Fields: first name, last name, email, phone, company, message, plus a hidden honeypot field and the Turnstile widget. It posts JSON to the Worker's URL with `fetch`.
2. **The Worker** (a few dozen lines of TypeScript):
   - Rejects anything that isn't a POST from the allowed origin, is too large, or has the honeypot filled.
   - Verifies the Turnstile token with Cloudflare's `siteverify` call, using the Turnstile secret.
   - Gets a token from `https://login.microsoftonline.com/<tenant>/oauth2/v2.0/token` with the client credentials and scope `https://<env>.crm4.dynamics.com/.default` (the confidential-client scope in [authenticate with OAuth](https://learn.microsoft.com/en-us/power-apps/developer/data-platform/authenticate-oauth)), and caches it until it expires.
   - Creates the Lead: `POST /api/data/v9.2/vibe_leads` with the mapped fields, Lead source = Website, Lead status = Not Contacted, and the Owner from a Worker setting. Returns 200 or a friendly error.
   - Keeps the client secret, tenant id and Turnstile secret as Worker secrets.
3. **In Dataverse:**
   - One Entra app registration (tenant admin) and one **application user** in `dev-salesapp` with a new security role, for example "Web lead intake": create on Lead only, no read. The Owner must be set explicitly, because otherwise the application user would own the Lead.
   - The process engine plug-in runs on create as for any Lead, so Entry criteria pick the Process and Business rules apply. A web Lead that breaks a "required" Business rule would be refused, so the Worker must send every field a Lead rule requires, or such rules must allow web Leads.
   - **Optional:** route the Worker through a custom API such as `vibe_SubmitWebLead` instead of a direct create. That moves validation, duplicate checking (same email as an open Lead or a Contact) and owner choice into C# next to the process engine, and the role then needs only the right to run that API. Start with the direct create; add the custom API when duplicate handling is wanted.
4. **Spam that gets through** still lands as a Not Contacted Lead, and the Owner can Disqualify it with reason Duplicate or Other. No new Disqualify reason is needed.

**Two practical checks:**
- Microsoft's app-registration quickstart lists "an Azure account that has an active subscription" as a prerequisite ([register an app](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app)). App registrations are a Microsoft Entra ID feature and are normally made in the Entra admin center of a Microsoft 365 tenant without a subscription. Confirm this on the developer tenant first.
- Cloudflare's pricing page doesn't say whether Workers Free asks for a card. Confirm at sign-up; if it does, the route still works from any other free serverless host, but Cloudflare is preferred because Turnstile comes from the same account.

## 3. How Salesforce, Dynamics 365 and HubSpot do it

| Product | How the form is made | Where it posts and how it authenticates | Spam protection | Limits and extras |
|---|---|---|---|---|
| **Salesforce Web-to-Lead** | Setup generates HTML for the chosen Lead fields; the form "needs to be hosted on a publicly accessible website" ([SalesforceBen guide](https://www.salesforceben.com/a-step-by-step-guide-to-creating-web-to-lead-forms-in-salesforce/), secondary) | A public Salesforce endpoint identified by the org id in the HTML; no visitor login | Optional "Require reCAPTCHA Verification"; failing requests make no Lead | 500 Leads per 24 hours; extra requests queue for the next day. Lead assignment rules set the Owner, auto-response rules send a reply email |
| **Dynamics 365 Customer Insights – Journeys** (needs its own licence; not Dynamics 365 Sales) | Form designer; target audience Lead, Contact, or Lead & Contact. A Lead target "creates a new lead, even if the email address was used before" ([create forms](https://learn.microsoft.com/en-us/dynamics365/customer-insights/journeys/real-time-marketing-form-create)) | Embedded with a JavaScript snippet or a standalone hosted page; the embedding domain must be authenticated or submissions are rejected | reCAPTCHA element | Duplicate handling per form; contact matching by email |
| **HubSpot** (forms are in the free CRM) | Form editor with embed code, or your own form | `POST https://api.hsforms.com/submissions/v3/integration/submit/{portalId}/{formGuid}`, which "supports cross-origin (CORS) AJAX requests" and declares no auth ([submit data](https://developers.hubspot.com/docs/api-reference/legacy/marketing/forms/v3-legacy/submit-data-unauthenticated)) | reCAPTCHA on the form (the API answers `FORM_HAS_RECAPTCHA_ENABLED` when it's on); `BLOCKED_EMAIL` checks | 429 when rate-limited; creates or updates the Contact by email |
| **This app (recommended)** | Own HTML form | Cloudflare Worker, application user | Turnstile, honeypot | 100,000 requests/day; default Owner from a setting; process engine applies on create |

What all three have and the recommendation copies: a public endpoint that hides the CRM credentials, a CAPTCHA checked server-side, a default Owner (Salesforce adds assignment rules), and the source set to "web". What it leaves out for now: auto-response emails and assignment rules. An auto-response could later be a Dataverse-triggered flow with the Outlook connector (Standard), linked to the app.

## Open points

1. **Licensing for production:** ask Microsoft (or a licensing partner) whether an application user creating Leads from an anonymous web form is allowed without Power Pages capacity, given the multiplexing rule on indirect creates ([multiplexing guidance](https://www.microsoft.com/licensing/guidance/Multiplexing)). Not a blocker on the developer tenant.
2. **Environment type of `dev-salesapp`:** the repo doesn't record whether it is a developer environment. If it is, premium flows (including the HTTP trigger) run free there for testing under the Developer Plan, but not for production.
3. **Spike:** make the Entra app registration and application user on the developer tenant (confirms no subscription is needed), then post one Lead from a local script with client credentials.
4. **Cloudflare sign-up:** confirm Workers Free and Turnstile need no card.
5. **Duplicate handling and auto-reply** are product decisions: whether a web Lead with a known email is merged, flagged, or created anyway (Customer Insights creates a new Lead every time), and whether the visitor gets an email.
6. **Power Pages CAPTCHA detail** wasn't re-checked on Learn for this note; it only matters if Power Pages is chosen later.
